# IEPL 白名单自动同步（Stash）

IEPL 前置服务器按「来源 IP 白名单」放行时，家宽 / 移动网络的出口 IP 会经常变化，每次都手动去后台添加很麻烦。
这个覆写让 Stash 自动完成：

- ⏱ **每 5 分钟**检测一次你的**直连出口 IP**，不在白名单里就自动添加；
- 🚀 **代理启动时立即检测一次**，之后再按 5 分钟节奏定时检测；
- 🧭 首页「面板」里的 Tile 显示当前直连 IP、是否在白名单、占用数量、检查时间；**点击 Tile 即手动同步**；
- 🔔 新增 IP、白名单已满（会顶掉最早一条）、连续失败 / 超时、恢复时发送通知，不会刷屏。

> ⚠️ **本仓库只包含 Stash 端（覆写 + 脚本）。** 它需要你自己有一个「同步服务」配合，接口见下文。
> 覆写里没有任何账号、密钥或地址，**使用前必须填上你自己的域名和 token**，否则脚本不会联网。

## 工作原理

```
Stash（直连 DIRECT）──POST /sync + X-Token──▶ 你的同步服务 ──调用 IEPL 白名单 API──▶ IEPL
                                                  │
                      服务端把“请求来源 IP”当作你的直连 IP，
                      不在白名单里就添加，并把结果（exists / added …）返回给 Stash
```

关键点：**白名单里记录的必须是你的直连出口 IP，而不是代理节点的 IP。** 所以请求同步服务的这一条
连接必须走 `DIRECT`——覆写里的 `prepend-rules` 规则和脚本请求头里的 `X-Stash-Selected-Proxy: DIRECT` 就是为此。
IEPL 的 API Key 只保存在你的服务端，**Stash 里只有访问同步服务的 token**，手机丢了也不会泄露 IEPL 密钥。

## 你需要的同步服务（接口约定）

脚本只依赖这一个接口：

```
POST {api}/sync
请求头  X-Token: <token>
```

成功（HTTP 200）：

```json
{
  "ok": true,
  "ip": "1.2.3.4",
  "status": "exists",
  "count": 3,
  "limit": 10,
  "mode": "ip",
  "whitelist": ["…"],
  "removed_ip": "仅在白名单已满、新增时顶掉了最早一条时返回"
}
```

- `status`：`exists` = 已在白名单；`added` = 刚刚新增。
- `count` / `limit`：当前占用 / 上限，用于面板显示与“已满”提示。
- `ip`：服务端看到的请求来源 IP（即你的直连出口 IP）。

失败：

```json
{ "ok": false, "msg": "失败原因", "ip": "可选" }
```

服务端实现要点（安全）：

1. **以连接的来源 IP 为准**，不要信任客户端在请求里传来的 IP，否则任何持有 token 的人都能往白名单写任意 IP。
2. 校验 `X-Token`（用常量时间比较），并对连续鉴权失败做限流。
3. 添加操作要幂等：同一个 IP 重复请求不应重复添加，也不应改变顺序。
4. 访问需 HTTPS；若白名单只允许 IPv4，域名只配 A 记录即可避免走 IPv6。
5. 建议在服务端缓存一小会儿白名单快照：客户端超时重试时直接命中缓存，不重复访问上游。

## 安装

1. **把 [`iepl-whitelist.stoverride`](./iepl-whitelist.stoverride) 的内容复制到 Stash 的本地覆写里**
   （Stash → 覆写 → 新建 / 导入本地文件；入口名称以你的 Stash 版本为准）。
   > 不要直接添加本仓库的远程覆写 URL：它里面是占位符，而 token 必须由你自己填写；
   > 远程覆写又无法在本地修改。
2. 打开覆写文件，把所有带 **★** 的占位符改成你自己的（见下表）。
3. 启用该覆写。
4. Stash → **策略组页左上角 ☁️ → 远程资源 → 更新**（首次需下载脚本），或断开 Stash 再连接一次。
5. 在首页「面板」里添加 **IEPL 白名单** Tile，点一下确认能显示直连 IP 与状态。

## 需要填写的自定义信息

| 占位符 | 在覆写里的位置 | 填什么 |
| --- | --- | --- |
| `YOUR_DOMAIN` | `prepend-rules` 里的 `DOMAIN,YOUR_DOMAIN,DIRECT` | 你的同步服务域名，**不带** `https://` |
| `YOUR_DOMAIN` | cron 与 tile 两处 `argument` 里的 `"api":"https://YOUR_DOMAIN"` | 同一个域名，**带** `https://`，不要以 `/` 结尾 |
| `YOUR_TOKEN` | cron 与 tile 两处 `argument` 里的 `"token":"YOUR_TOKEN"` | 访问同步服务的 token |

三处域名必须一致；两处 `argument` 的 `api` / `token` 也必须一致。`argument` 是一个 JSON 字符串，
修改时注意保留引号和逗号。仍为 `YOUR_…` 时，Tile 会显示「尚未配置」，cron 不会联网。

## Tile 状态

| 标题 | 颜色 | 含义 |
| --- | --- | --- |
| IEPL 白名单 ✅ | 🟩 绿 | 直连 IP 已在白名单 |
| IEPL 白名单 🆕 | 🟩 绿 | 刚刚新增（10 分钟内） |
| IEPL 白名单 ⚠️（显示数量） | 🟧 橙 | 白名单已满，下次新增会顶掉最早一条 |
| IEPL 白名单 ⚠️（显示“网络超时”） | 🟧 橙 | 连不上同步服务；保留上次成功状态，会自动重试 |
| IEPL 白名单 ❌ | 🟥 红 | 服务端明确报错（如 token 无效），会显示原因 |
| IEPL 白名单 ⚙️ | ⬜️ 灰 | 尚未配置：还没填 `YOUR_…` 占位符 |

## 同步节奏

覆写里的 cron 每分钟触发一次，但脚本在本地先判断，**只有这几种情况才联网**：

1. 代理刚启动（距上次 cron 超过 150 秒，说明期间代理是关着的）；
2. 距上次检查已满 5 分钟；
3. 上次失败，且已过 1 分钟（失败重试）。

点击 Tile（或面板刷新）总是立即同步。检测间隔写在脚本顶部的 `INTERVAL` 常量里。

## 常见问题

- **Tile 一直显示「网络超时」**：先确认同步服务的域名走的是 `DIRECT`（Stash 的请求/日志里查看该域名的策略）。
  Stash 的 `$httpClient` 默认超时约 5 秒，脚本放宽到 8 秒并最多重试 3 次；服务端收到请求后会一直做完，
  所以超时多数时候并不意味着添加失败，下一次检查会显示“已在白名单”。
- **白名单里记录的是代理节点 IP**：说明同步请求没有走直连。检查覆写里的 `DOMAIN,YOUR_DOMAIN,DIRECT` 是否已改成你的域名，
  并且没有被更靠前的规则抢先命中。
- **白名单很快被占满**：出口 IP 在一个地址池里频繁变化时，每变一次就新增一条，满额后会顶掉最早的一条。
  这是单 IP 白名单的固有限制；可以让服务商添加网段，或让服务端在新增前清理你自己之前加的旧 IP。
- **iOS 后台限制**：cron 依赖 Stash 的网络扩展保持运行；被系统挂起期间不会触发，恢复后会按“代理刚启动”立即补一次。

## 隐私与安全

- 脚本与覆写里**不含**任何 API Key、上游接口地址或你的域名；它们只存在于你自己的服务端和你本机填写后的覆写里。
- **token 等同于白名单的写入权限**：请勿把填好的覆写提交到公开仓库、截图外传或分享给他人；
  怀疑泄露时在服务端更换 token，并同步更新所有设备上的覆写。
